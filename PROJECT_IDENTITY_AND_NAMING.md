# Project Identity and Naming Transition

## Repository identity

**PANCAKE** = **Pathfinding for Acquisition of Necessary Commodities using Algorithmic Knowledge Efficiently**

PANCAKE remains the repository/software identity and the historical name of the original route-planning implementation.

## Working paper title

**Representation, Neighborhood Semantics, and Metaheuristic Mechanism Transfer in the Traveling Purchaser Problem**

## Naming policy for the research layer

The research materials are being progressively separated from the repository codename.

- Use **PANCAKE** only for the repository, software GUI, legacy implementation lineage, and historical notes.
- Use **controlled synthetic benchmark**, **commodity-centric representation**, **market-tour representation**, or **official TPPLIB study** in scientific text.
- Do not use the PANCAKE name as evidence, a benchmark class, a scientific mechanism, or a contribution label.
- Figure titles and table captions should describe the measured phenomenon rather than the project codename.
- New manuscript files should use the working paper title or neutral TPP/metaheuristic terminology.
- Legacy filenames and source-code namespaces may remain temporarily to preserve reproducibility; they can be renamed in later migration stages after dependency checks.

## Migration stages

1. **Stage 1 — manuscript and figure language:** completed in the current revision.
2. **Stage 2 — README/research-document terminology:** initiated in this revision.
3. **Stage 3 — research folder/file renaming:** pending dependency-safe migration.
4. **Stage 4 — source-code namespace / GUI branding cleanup:** optional and should be done only after regression tests.
